# 01 — DSH Desktop 架构解读（完整运行逻辑）

> 基于 master（commit `9a47f0d8e0`）源码阅读。上游锁定：DeepSeek Harness `0.2.1-rc.3`（stable）/ `0.2.2-rc.5`（beta/next），见根目录 `upstream.json`。

## 1. 总体分层：一个"薄 Electron 宿主 + 插件组合的运行时"

```
┌─────────────────────────────────────────────────────────────┐
│ Electron main（main.ts，薄壳）                                │
│  单实例锁 → Profile launcher → 启动 Host 子进程                │
│  BrowserWindow 加载 loopback URL / 托盘 / 终端 / 更新          │
└──────────────┬──────────────────────────────────────────────┘
               │ 子进程（ElectronRuntime ↔ Host）
┌──────────────▼──────────────────────────────────────────────┐
│ DSH Host（Cordis 运行时，上游代码原样运行）                     │
│  agent / model / tool / session / settings / webServer       │
│  + Desktop 注入的 Host 插件（desktop-shell/terminal/…）       │
│  + 第三方插件（用户 Profile 组合）                              │
└──────────────┬──────────────────────────────────────────────┘
               │ HTTP + WebSocket Web carrier（默认仅回环监听）
┌──────────────▼──────────────────────────────────────────────┐
│ Web Client（沙箱渲染层）                                       │
│  上游官方 Web UI（dsh-web-app bundle）                        │
│  + Desktop client 插件（帧/标题栏/设置/向导，slot 组合）        │
└─────────────────────────────────────────────────────────────┘
```

核心设计哲学：**万物皆插件**。桌面对上游源码零修改——上游 DSH 原样运行；桌面壳（窗口、托盘、终端、更新、Profile）本身以 Cordis 插件身份与上游能力组合进同一个运行时。这是 fork 改造的合法性基础：我们改"插件"，不动"运行时"。

## 3. 启动顺序（main.ts + electron-runtime.ts + index.ts）

1. **单实例锁**：`app.requestSingleInstanceLock()`；读私有 profile/mode 状态。
2. **身份**：`app.setName(PRODUCT_NAME)`；Windows 上 `app.setAppUserModelId(DESKTOP_APP_ID)`。两者均来自 `src/product-identity.ts`（本次已改）。
3. **Profile launcher**：`desktopProfiles.current` 提供 profile 名与绝对目录；`list()` 只读发现，`select()` 记录 pending target 并通过重启生效。
4. **Host 启动**：Launcher 提供当前 generation 的 native runtime、`desktopProfiles` bootstrap、内置 pnpm。Host Cordis root 启动 Loader entries，Desktop service 先于第三方插件注册。
5. **Web carrier**：官方 `dsh-base`、`dsh-web-app` 与用户 Profile 中的第三方 bundle 组成 HTTP+WebSocket carrier，默认绑定 loopback（可选局域网，无鉴权，危险）。
6. **窗口**：Electron 创建 BrowserWindow，从 loopback 地址加载同源页面；URL 携带 `dsh-desktop-mode` 等环境参数（`index.ts:132`）。
7. **托盘**：Web surface 加载成功后才创建托盘并提交 last-known-good 状态。

任何 profile/mode 切换都会 **dispose 当前 generation 再启动新的**——Service reference、窗口对象、子进程句柄一律不跨 generation 缓存（`ElectronShellGeneration` 幂等 `release()`）。

## 4. 三种 Shell 模式（UI 改造的关键分层）

| 模式 | 布局所有权 | 说明 |
| --- | --- | --- |
| `compatibility`（原默认） | 上游 | Desktop 只通过 overlay slot 加一条 36px 独立帧（`compatibility-chrome`），上游 layout/root/sidebar/conversation 完全不动 |
| `extended` | 混合 | 禁用上游 root layout，Desktop 安装自有 layout/sidebar surface，倒 L 材质 frame 中继续承载上游 sidebar/conversation/details occupant |
| `advanced` | **Desktop** | 禁用上游 root layout，Desktop 注册自己的 **root slot**（`AdvancedFrame`）：三栏 grid（sidebar｜main｜rightbar）+ overlay + 拖拽 resize；上游 sidebar/conversation 作为 occupant 渲染进 Desktop 的栏位 |

模式由 `dsh-plugin-desktop/cordis.patch.yml` 中 `desktop-shell.config.mode` 决定，用户可在标题栏"演示模式"弹层实时切换（写入设置后重启 renderer 生效）。**本次 fork 已将默认值改为 `advanced`** —— PolyMechanism Studio 拥有自己的品牌化布局骨架。

## 5. 客户端插件如何"改 UI"（Client faces）

`src/client/index.ts` 是 Desktop 客户端插件入口，通过 Cordis client context：

- `ctx.slots.register({ name: 'root', … }, AdvancedFrame)` — 占据 root 插槽，成为整个应用布局（`advanced-shell.ts:43-52`）。
- `layout service`（`layout-service.ts` / `layout-state.ts`）— 自有面板状态：sidebar 宽度/折叠、rightbar 比例、窄视口自动折叠。
- `theme presenter` — 跟随上游主题变化应用 Desktop 材质。
- `installSidebarFooterStyles()` — 侧栏 footer 座位样式（所有模式共享）。
- `registerDesktopOnboarding()` — 首启 Setup Wizard（可嵌入上游导航渲染）。
- `registerPluginControls()` — 插件控制面板；`applyDesktopSettings()` — 桌面设置区。
- 环境解析：`parseDesktopClientEnvironment(window.location.search)` → `{ mode, platform, material, version }`。

上游能力通过 type-only import 收敛：`@deepseek-ai/dsh-client-ui-{conversation,session,sidebar,settings,theme,renderer,workspace}` 等——Desktop UI 不直接调 Electron API，一切经共享 carrier。

原生小窗口（不进 Web Client 组件树）位于 `src/native-ui/`：setup-wizard、profile-selector、profile-create、recovery、desktop-dialog（`DesktopDialogWindow` 独立沙箱模态窗）——各自是独立 Vite 入口的 React 应用（shadcn/ui）。

## 6. Host 侧服务边界

- **上游 Host**：agent、model、tool、session、settings、webServer、subprocess 等官方能力。
- **Desktop Host 插件**（cordis.patch.yml 注入）：`desktop-shell`（native shell generation）、`desktop-terminal`、`desktop-diagnostics`、`desktop-notifications`、`desktop-pnpm`、`desktop-profiles`、`desktop-updates`。
- **对第三方开放的公开 contract**（稳定通道）：`dsh-plugin-desktop/profile-service` 与 `dsh-plugin-desktop/pnpm`。`desktopRuntime`/`desktopPnpmBootstrap` 等是 launcher 私有能力，非第三方 API。
- **平台差异**集中在 `ElectronPlatformStrategy`（Windows/macOS/Linux adapter：目录选择、shell 模式切换、更新下载、菜单、Dock、原生材质）。

## 7. Profile / 打包 / 更新

- **Profile**：一组插件组合的运行环境。`desktopPnpm.run()` 跑内置 pnpm；`runPlugin()` 经打包的 DSH CLI 维持 profile 初始化与 bundle reconcile。数据根目录 `~/.dsh`（stable）/ `~/.dsh-beta`（beta）——本次 fork 暂保留该目录名以兼容现有 profile 数据（见执行计划 Phase 0.2）。
- **打包**：Electron Builder + `app.asar`；需物理落盘的依赖（pnpm、node-pty、Windows ACL）放 `app.asar.unpacked`；packaged runtime gate 校验 ASAR 与物理双入口。身份：`appId`（本次改为 `studio.polymechanism.desktop`）、`productName`（改为 `PolyMechanism Studio`）、产物名 `PolyMechanism-Studio-${version}-*`。
- **更新**：版本检查与安装包下载均携带 `X-DSH-Desktop-Channel` / 版本 header。fork 已将 `DESKTOP_VERSION_ENDPOINT` 与 `DESKTOP_DOWNLOAD_URLS` 切至 `updates.polymechanism.dev` 占位——**上线自动更新前必须自建发行服务**，此前更新检查会静默失败（安全行为）。
- **通道**：stable 与 beta 是两个实体 npm 包与两个系统应用（非 Git 分支区分）；`upstream.json` 记录各通道的上游版本/commit/runtime 清单。

## 8. 对 PolyMechanism 的启示（为什么这样改）

1. **改 UI 的正确位置**是 `dsh-plugin-desktop/src/client/`（Desktop-owned client faces）与 `src/native-ui/`（原生小窗）——不需要也不允许改上游子模块。
2. **要占据布局**，用 advanced/extended shell 的 root slot 注册；要加科研面板，注册 sidebar/main/rightbar/shell.overlay 的插槽组件（见 02 文档的四级模型）。
3. **要加领域业务**，模仿 desktop-* 插件写 Host 插件（research-manager、evidence-ledger…），经 `cordis.patch.yml` 组合进 Profile；工具面以 `defineTool` 注册给 Agent；重计算走 Python MCP。
4. **版本与渠道纪律**：stable/beta 变体镜像规则（先 beta 后 stable，`yarn check:desktop-variants`）——fork 阶段可以只跟随 stable，但要记录 beta 待办。
