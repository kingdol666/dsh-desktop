# 05 — 系统架构设计（前后端 / 数据 / API）

> 依据：`docs/polymechanism/01-架构解读.md`（运行时）、`04-调研与复用矩阵.md`（复用决策）、用户 taste 裁决（混合知识网络 / kb-rag+zotero / CAE+表征 / 一步到位 Dockview）。所有 API 形状以 vendored 0.2.1-rc.3 实际契约为准，不允许凭记忆臆造。

## 1. 分层架构

```
┌──────────────────────────────────────────────────────────────────────────┐
│ L5  UI 层（PolyMechanism Research Workbench，自研 client 插件）             │
│   Dockview 工作台：项目树 │ 多面板标签 │ Inspector │ 命令面板 │ 状态栏       │
│   宿主：advanced shell 的 root slot（Desktop 已拥有，直接渲染）              │
├──────────────────────────────────────────────────────────────────────────┤
│ L4  Agent 层（Preset + Skill + 委派）                                      │
│   6 专家 Preset（persona + 工具白名单） │ skills/*/SKILL.md │ subagent 委派 │
├──────────────────────────────────────────────────────────────────────────┤
│ L3  领域服务层（自研 Cordis Host 插件 packages/pm-plugins）                  │
│   pmProjects · pmEvidence · pmHypotheses · pmMechanism · pmModels          │
│   pmKnowledge(RSI) · pmGate · pmScience(客户端)                            │
│   工具注册：defineTool → polymer_* / pm_*                                  │
├──────────────────────────────────────────────────────────────────────────┤
│ L2  适配层（复用 + 薄封装）                                                 │
│   文献：dsh-kb-rag(kb_*) · dsh-zotero-skill                                │
│   记忆：dsh-mnemon 或 memory-eternal                                      │
│   官方：agent-preset / skill / storage-domain / workflow / mcp-client      │
├──────────────────────────────────────────────────────────────────────────┤
│ L1  引擎层                                                                │
│   DSH 运行时（vendored，零修改）                                            │
│   Science Engine：既有 CAE/光学（Node）+ 表征分析（Python）via MCP          │
└──────────────────────────────────────────────────────────────────────────┘
```

**边界铁律**：L5 只依赖 L3 的远程服务与 L1 的会话流；L3 只依赖 L2/L1 的公开服务；**L3 不得 import L5**；`packages/pm-domain`（纯类型/zod）不得 import 任何 `@deepseek-ai/*`/`electron`/`node:*`。

## 3. 领域数据模型（pm-domain）

### 3.1 实体

```ts
// 统一 ID：type + 单调序号 + 短哈希，如 EV-000123-7f3a
type EntityId = string

interface ResearchProject {
  id: EntityId; title: string; question: string;      // 科研问题
  domain: 'pva-optical-film' | 'generic-polymer';
  status: 'active'|'paused'|'archived';
  createdAt: string; milestones: Milestone[];
  linkedWorkspaces: string[];                          // DSH workspace ids
  agentPreset: string;                                 // 默认专家
}

interface Observation {                                // 观测（原始事实）
  id: EntityId; projectId: EntityId;
  kind: 'experiment'|'cae'|'characterization'|'literature'|'simulation';
  payload: Record<string, unknown>;                    // 结构化数值
  artifact?: { path: string; sha256: string; mime: string };
  capturedAt: string; operator: 'human'|'agent'|'import';
}

interface Evidence {                                   // 证据（被登记、可引用）
  id: EntityId; observationId?: EntityId;
  claimSupport: string;                                // 它支持/反驳什么（一句话）
  polarity: 'supports'|'refutes'|'neutral';
  strength: 'strong'|'moderate'|'weak';
  sourceRef: { type:'doi'|'dataset'|'file'|'run'; ref:string };
  hash: string;                                        // 内容哈希（防篡改）
  recordedBy: string; recordedAt: string;
}

interface Hypothesis {
  id: EntityId; projectId: EntityId; statement: string;
  mechanismEdgeIds: EntityId[];                        // 关联的机理边
  competitors: EntityId[];                             // 竞争假设
  discriminatingTest?: { design: string; observable: string; expectedIfTrue: string; expectedIfFalse: string };
  status: 'proposed'|'conditional'|'under_test'|'supported'|'refuted'|'archived';
  evidenceIds: EntityId[]; transitions: TransitionLog[];
}

interface MechanismNode {
  id: EntityId; projectId: EntityId;
  type: 'process'|'structure'|'property'|'condition'|'material';
  name: string; symbol?: string; unit?: string;
  aliases: string[]; description?: string;
  source: 'textbook'|'literature'|'cae'|'experiment'|'agent';
}

interface MechanismEdge {                              // ★核心：带条件与证据的物理关系
  id: EntityId; projectId: EntityId;
  from: EntityId; to: EntityId;
  relation: 'increases'|'decreases'|'determines'|'couples'|'competes'|'mediates';
  equation?: string;                                   // LaTeX
  conditions: { temperature?: [number,number]; strainRate?: [number,number];
                drawRatio?: [number,number]; materialState?: string[]; note?: string };
  applicability: 'established'|'candidate'|'disputed'|'refuted';
  theorySource?: { doi?: string; textbook?: string; chapter?: string };
  confidence: number;                                  // 0..1（人工/审查给定）
  openQuestions: string[];
  createdBy: 'seed'|'agent'|'human'; createdAt: string;
}

interface ModelSpec {                                  // 可执行科学资产
  id: string; name: string;                            // e.g. 'kww-relaxation'
  domain: 'rheology'|'optics'|'orientation'|'crystallization'|'thermo';
  equations: string[];                                 // LaTeX
  params: { name: string; unit?: string; min?: number; max?: number; prior?: string }[];
  validRange: Record<string, [number,number]>;
  implementation: { engine:'mcp'; tool:string };        // 指向 MCP 工具
  referenceData: { path: string; hash: string }[];
  status: 'draft'|'validated'|'deprecated';
}

interface KnowledgeCard {                              // RSI 单元
  id: EntityId; scope: 'global'|'project'|'agent:<presetId>';
  kind: 'fact'|'method'|'pitfall'|'decision'|'edge-candidate';
  title: string; body: string;                         // Markdown
  links: { nodeIds?: EntityId[]; edgeIds?: EntityId[]; evidenceIds?: EntityId[] };
  status: 'pending'|'approved'|'rejected'|'superseded';
  origin: { taskId?: string; sessionId?: string; agent: string; at: string };
  reviewedBy?: string; reviewedAt?: string;
}
```

### 3.2 不变量（代码强制，非提示词约定）

1. `Evidence.hash` 必须等于其 `payload+sourceRef` 的 SHA-256；写入后不可修改（append-only）。
2. `Hypothesis` 进入 `supported`/`refuted` 必须满足：`evidenceIds.length ≥ 2` 且至少 1 条 `strength:'strong'`，且存在 `discriminatingTest`。
3. `MechanismEdge.applicability='established'` 必须有 `theorySource` **且** 至少 1 条 `polarity:'supports'` 的 strong 证据；否则最高只能 `candidate`。
4. 任何 `KnowledgeCard` 从 `pending → approved` 必须记录 `reviewedBy`（reviewer agent 或 human）。
5. 结论类文本（`Claim`）必须携带 `evidenceIds`，空引用直接拒绝写入。

## 4. 存储策略

| 数据 | 方案 | 理由 |
| --- | --- | --- |
| 项目 / 假设 / 模型注册表 | `dsh-storage-domain`（JSON backend，`per-record` 布局） | 官方已装、零风险；实体量小、需可读可 diff |
| 证据账本 | **自研 append-only JSONL**（`<project>/.pm/evidence.jsonl`）+ 启动重建内存索引 | 需要不可篡改 + 可 git 审计；官方 storage 无 append-only 保证 |
| 机理图谱 | **自研 JSON 快照 + 内存图索引**（`mechanism.json` + `graph.index`） | 节点量预期 <5k，内存索引足够；需要邻域查询与路径搜索（自研） |
| 知识卡（RSI） | Markdown 文件（`knowledge/cards/<scope>/<id>.md`）+ frontmatter | 可 git 管理、人可读、与 `memory-eternal` 形态一致 |
| 会话/审计 | DSH 原生 session + `dsh-session-query-sqlite` | 已装，直接查 |
| 大规模升级路径 | 补装 `dsh-storage-sqlite`（vendor tgz 已有） | 节点/证据 > 5k 或需 SQL 聚合时切换；`pm-core` 通过 repository 接口隔离，不返工 |

**统一通过 `pm-core` 的 repository 接口访问**：`EvidenceRepo`、`HypothesisRepo`、`MechanismRepo`、`KnowledgeRepo`。上层不感知存储实现。

## 5. 后端服务（Cordis Host）

### 5.1 服务清单（`plugins/pm-research/src/services/`）

| 服务名（inject key） | 职责 | 关键方法 |
| --- | --- | --- |
| `pmProjects` | 项目管理 | `create/list/get/update/archive/linkWorkspace` |
| `pmEvidence` | 证据账本 | `record/query/get/verifyChain` |
| `pmHypotheses` | 假设状态机 | `propose/transition/list/get/attachEvidence` |
| `pmMechanism` | 机理图谱 | `upsertNode/upsertEdge/neighbors/pathSearch/queryByCondition/attachEvidence` |
| `pmModels` | 模型注册表 | `list/describe/validate/fit` |
| `pmKnowledge` | RSI 知识 | `propose/approve/reject/query/supersede` |
| `pmGate` | 科学门控 | `evaluate(kind, payload) → {verdict, reasons[], requiredEvidence[]}` |
| `pmScience` | 科学计算门面 | `caeRun/caeStudy/opticsAnalyze/waxs/ftir/saxs` |

**注册方式**（与官方 `agentPresets` 同构）：`class PmEvidence extends Service { constructor(ctx){ super(ctx,'pmEvidence') } }` + `declare module '@deepseek-ai/cordis' { interface Context { pmEvidence: PmEvidenceService } }`。

### 5.2 工具注册（Agent 可见）

统一在 `plugins/pm-research/src/tools/`，每个文件一个 `defineTool`，`apply(ctx)` 内 `ctx.tools.register(...)`。**受 `defineTool` schema 限制**（不支持 `min/max/pattern/anyOf`）：

- 数值范围校验放在 `execute` 内（抛结构化错误），不写在 schema 里；
- 枚举一律用 `enum`；可选字段不写 `required`；
- `output.schema` 用 `{type:'object', additionalProperties:false, properties:{...}}` 显式声明。

工具名与契约见 `09-API与工具契约.md`。

### 5.3 Scientific Gate 规则（`pmGate`）

借鉴 `chelate-shell` 的"可证伪门禁"思想，落到高分子：

| 规则 ID | 触发 | 检查 |
| --- | --- | --- |
| `G-UNIT` | 任何含方程的写入 | 量纲一致性（取向因子无量纲、双折射无量纲、应力 MPa、温度 K/℃ 显式） |
| `G-EVID` | 结论/边升级 | 证据引用非空 + 哈希可验 + 极性匹配 |
| `G-COMPETE` | 假设 → supported | 至少列出 1 个竞争假设且已排除（有 refuting 证据或明确不适用条件） |
| `G-RANGE` | 模型调用 | 参数落在 `validRange`；越界返回 `warn` 并降级 `confidence` |
| `G-OPTICS` | 光学结论 | 双折射/相位差/取向因子三者数量级与符号自洽（`Δn = f·Δn₀` 关系检查） |
| `G-DOI` | 引用文献 | DOI 走 Crossref 解析（复用 kb-rag 或自研 fetch），失败标 `unverified` |

## 7. 前端架构（Dockview 一步到位）

### 7.1 关键决策：自建 Dockview，不用官方 dockkit

- 官方 `dsh-client-ui-dockkit` **未安装且自述为 internal engine**，`sidebar-right` 运行时依赖它（当前构建存在 `require.resolve` 失败隐患）→ **不可作为公共 API**。

- 风险隔离：若 `dockview` 与 React 版本冲突，降级为自研 3 列 + 可拖拽分隔条（`AdvancedFrame` 已有 `ResizeHandle` 可复用）。

## 8. 前后端交互设计

### 8.1 两条通道，职责分离

| 通道 | 用途 | 机制 |
| --- | --- | --- |
| **Agent 通道** | 模型调用业务（Agent 是主要操作者） | `defineTool` → `polymer_*`/`pm_*`，结果进会话流 |
| **UI 通道** | 人直接操作（点按钮、拖拽、审核） | Client 插件 → Host 服务（Typert Remote，与 `agentPresets` 同构）；失败降级为 `webServer` 自定义 HTTP route |

### 8.2 UI 通道契约（示例）

```ts
// ui/pm-workbench/src/api.ts —— 通过 connection 拿到远程服务代理
const project = await ctx.remote.pmProjects.get(projectId)          // 读
await ctx.remote.pmEvidence.record({ observationId, polarity, ... }) // 写（服务端校验）
await ctx.remote.pmKnowledge.approve({ cardId, reviewer: 'human:me' })
```

降级 HTTP（若 remote 不可用）：`GET/POST /pm/<service>/<method>`，body 为 JSON，统一返回 `{ok:true,data}` / `{ok:false,error:{code,message,details}}`。

### 8.3 事件与实时性

- **Agent 执行流**：复用 DSH session 事件流（已有 streaming），UI 只需订阅。
- **业务状态变更**：Host 服务在写操作后 `ctx.emit('pm/<entity>/changed', {id})`；UI 订阅并增量刷新（不做全量轮询）。
- **长任务（CAE）**：`pmScience.caeRun` 走 `dsh-tool-jobs` 后台任务，UI 订阅 job 进度事件；会话中显示进度卡。

### 8.4 一致性规则

- UI **不做乐观写入**（证据/假设/知识均为科研事实，必须服务端确认后刷新）。
- 所有写操作返回 `{entity, revision}`；UI 用 `revision` 做冲突检测（`expected_revision` 模式，与官方 `team_task_update` 一致）。
- 失败必显示结构化错误（code + 可操作建议），不静默。

## 9. 页面与流程（端到端）

```
1. 新建项目 → pmProjects.create（question + domain）
2. 导入数据 → 文件拖入 characterization 面板 → 解析 → Observation
3. 文献 → kb_search/kb_rag → 选中 → pmEvidence.record(literature)
4. 假设 → Agent 提议（pmHypothesis.propose）→ 看板出现
5. 机理 → Agent 查图（pmMechanism.queryByCondition）→ 候选路径 → 提边（candidate）
6. 计算 → physics-lab 设参 → cae_run（后台）→ 结果登记 Evidence
7. 判别 → 生成 discriminatingTest → 设计实验 → 结果回填
8. 审查 → pmGate.evaluate → Reviewer Agent 出 Objection → 人审批
9. 沉淀 → pmKnowledge.propose → 审核 → approved（RSI 积累）
10. 报告 → 证据包导出（WritingPacket：证据+图+参数+审查记录）
```
