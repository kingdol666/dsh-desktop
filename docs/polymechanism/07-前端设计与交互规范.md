## 1. 五条设计原则（冲突时按序裁决）

1. **数据先于对话**：屏幕主角是数据、图、参数、证据；对话是操作方式之一，不是界面中心。
2. **可追溯性可视**：任何结论都能一键下钻到证据 → 观测 → 原始文件。悬空结论必须是显眼的视觉缺陷。
3. **密集但不拥挤**：科研用户能接受高信息密度，但每个像素要有层级。默认 13px 正文、紧凑行高、清晰分区。
4. **状态永远可见**：当前项目、当前假设、数据新鲜度、门控状态、Agent 正在做什么——任何时候都能回答"现在是什么情况"。
5. **可逆与可审计**：破坏性操作必须二次确认并显示影响面；历史只追加。

## 2. 视觉系统

### 2.1 色彩（深色优先，浅色必需）

以桌面壳既有的 `--dsw-alias-*` 为基座，只新增语义层 `--pm-*`，**不覆盖上游 token**：

```css
:root {
  /* 表面层级：0 底 → 3 浮起 */
  --pm-surface-0: var(--dsw-alias-bg-base);
  --pm-surface-1: var(--dsw-alias-bg-layer-1);
  --pm-surface-2: var(--dsw-alias-bg-layer-2);
  --pm-surface-3: color-mix(in srgb, var(--pm-surface-2) 88%, #fff 12%);

  /* 分隔与描边：低对比，避免"格子感" */
  --pm-border-subtle: color-mix(in srgb, var(--dsw-alias-border-l1) 60%, transparent);
  --pm-border-strong: var(--dsw-alias-border-l1);

  /* 语义色：科研状态，不做装饰 */
  --pm-accent: oklch(0.72 0.14 250);        /* 主操作 / 选中 */
  --pm-evidence: oklch(0.74 0.12 160);      /* 证据 / 支持 */
  --pm-refute: oklch(0.66 0.17 25);         /* 反驳 / 冲突 */
  --pm-candidate: oklch(0.78 0.13 85);      /* 候选 / 待验证 */
  --pm-established: oklch(0.70 0.10 200);   /* 已确立理论 */
  --pm-pending: oklch(0.75 0.10 300);       /* 待审 / RSI 卡 */

  /* 数据可视化序列（色盲友好，10 色） */
  --pm-series-1: #4c8dff; --pm-series-2: #23b58a; --pm-series-3: #e8833a;
  --pm-series-4: #b968e0; --pm-series-5: #e0c341; --pm-series-6: #3fb6d8;
  --pm-series-7: #d95f6e; --pm-series-8: #6fbf5a; --pm-series-9: #8a8fe8;
  --pm-series-10: #b08968;
}
```

**规则**：
- 语义色只用于状态（证据/反驳/候选/已确立/待审），**绝不用于装饰性色块**。
- 图表序列色固定顺序，同一物理量在所有面板用同一颜色（如双折射恒为 `series-1`）。
- 对比度：正文 ≥ 4.5:1，图表线 ≥ 3:1；浅色模式下同步校验。

### 2.2 排版

| 用途 | 字号/行高 | 字重 | 字体 |
| --- | --- | --- | --- |
| 面板标题 | 12px / 16 | 600，字距 +0.02em，大写可选 | UI 无衬线 |
| 区块标题 | 14px / 20 | 600 | UI |
| 正文 | 13px / 20 | 400 | UI |
| 数据表/数值 | 12.5px / 18，等宽数字（`font-variant-numeric: tabular-nums`） | 400 | 等宽 |
| 证据/参数标签 | 11px / 14 | 500 | UI |
| 公式 | KaTeX 1.05em | — | KaTeX |
| Markdown（会话/知识卡） | 14px / 22 | 400 | UI + 代码等宽 |

数值永远等宽对齐；单位用次级色、小一号（`MPa`、`℃`、`s⁻¹`）。**禁止裸数字**：数值必须带单位或量纲说明。

### 2.3 间距与圆角

- 4px 基准栅格；面板内边距 12/16px；分组间距 8/12/24px。
- 圆角：控件 6px、卡片 8px、面板 0（贴合边缘）、浮层 10px。
- 阴影：仅浮层（`0 8px 24px rgb(0 0 0 / 28%)`）；面板之间用 1px 分隔线，不用阴影。

### 2.4 图标

`lucide-react`，16px 线性图标，`stroke-width: 1.75`；语义图标固定映射（Evidence=ShieldCheck、Hypothesis=FlaskConical、Mechanism=Network、CAE=Boxes、Literature=BookOpen、Knowledge=Brain）。

### 3.1 左栏（Project Rail，固定 280px，可折叠至 48px）

- **项目选择器**（顶部）：当前项目名 + 切换；`⌘/Ctrl+P`。
- **科研树**：项目 → 里程碑 → 任务/假设/数据集/报告；支持折叠、拖拽排序、状态点（候选/进行中/完成）。
- **筛选器**：只看"待验证假设 / 未绑定证据 / 我的任务"。
- 底部：知识卡入口（pending 数徽章）、设置。

### 3.2 中区（Dock）

- 标签：`Scientist`（会话）、`Mechanism`、`Characterization`、`Physics Lab`、`Literature`、`Evidence`、`Hypothesis`、`Report`。
- 支持：左右/上下分屏、拖出成浮窗、布局保存（按项目记忆）。
- **默认布局**：`Scientist` 左 60% + `Mechanism` 右 40%（新建项目时）。
- 标签关闭 = 卸载但不丢状态（`keepMounted` 语义自实现）。

### 3.3 右栏（Inspector，320px，随选中变化）

按选中实体自适应：Observation / Evidence / Hypothesis / Edge / Model / Card。固定三段：
1. **Identity**：名称、类型、状态徽章、ID（可复制）。
2. **Properties**：结构化字段（单位、条件、数值），可内联编辑（受权限）。
3. **Links**：证据、关联假设、关联边、来源任务/会话（可跳转）。

### 3.4 状态栏（28px）

`项目名 · 3 假设（1 待审） · 42 证据 · Gate: 2 warnings · CAE: 运行中 62% · 模型: kww ok · 已连接`

状态栏是可点击的：点 Gate → 打开门控详情；点 CAE → 打开任务面板。

## 4. 各面板交互规格

### 4.1 Scientist（会话）

- 复用上游 conversation（`renderSlot('main',{}, {entryKey:'conversation'})`），**不重写聊天**。
- 会话头部注入：当前专家 Preset 选择器 + 项目上下文条（当前假设/数据集）。
- Agent 输出的**结论块**特殊渲染：若消息含 `evidenceIds`，渲染为「Claim Card」——标题 + 极性徽章 + 证据 chips（点击开 Inspector）+ "查看推理链"。
- 工具调用卡：`cae_run` 显示进度与参数摘要；`pm_evidence_record` 显示新增证据卡；失败显示结构化错误 + 重试。
- 输入框增强：`@` 引用实体（假设/证据/数据集），`/` 调用 skill，拖入文件自动转为 Observation 提议。

### 4.2 Mechanism（机理图谱）★

```
┌───────────────────────────────────────────────────────────┐
│ 工具条: [搜索节点] [条件过滤: T / λ / rate] [布局: 力导向|分层] │
├───────────────────────────────────────────────────────────┤
│                                                           │
│    (拉伸比) ──increases──▶ (分子链取向) ──determines──▶ (双折射) │
│        │                        │                          │
│        └── 条件: T∈[80,140] ────┘   [证据 3 ✓ | 冲突 1 ⚠]      │
│                                                           │
├───────────────────────────────────────────────────────────┤
│ 图例: ● 已确立  ◐ 候选  ○ 争议  ✕ 已反驳 | 边宽=置信度         │
└───────────────────────────────────────────────────────────┘
```

- 节点形状编码类型（过程=圆角矩形、结构=六边形、性能=菱形、条件=胶囊、材料=方）。
- 边：实线=已确立、虚线=候选、红色=有冲突证据；线宽映射 confidence；标签显示 relation。
- 交互：
  - 点击节点/边 → Inspector 显示条件、方程（KaTeX）、证据列表、open questions。
  - **路径查询**：选中两个节点 → 高亮所有路径（≤4 跳），显示每条路径的证据强度与适用条件。
  - **条件过滤**：拖动 T/λ 滑块，不满足条件的边淡出（20% 不透明）——这是"当前工况下哪些机理可能成立"的核心交互。
  - 右键边 → 提议修改（生成 `pm_knowledge_propose` 草稿，需审查）。
- 空状态：显示"从文献/CAE 生成初始机理"引导 + 导入种子图谱按钮。

### 4.3 Characterization（表征数据）

- 顶部：数据集选择 + 元数据条（样品、工艺、测量条件、数据新鲜度）。
- 主体：图表区（ECharts）+ 拟合控制区（右内嵌）。
  - WAXS：1D 曲线 + 峰标注 + 结晶度读数；2D 图可切换热图。
  - FTIR：谱图 + 峰分解（分峰着色）+ 指数（氢键/羰基）。
  - SAXS：log-log 曲线 + Guinier/Porod 区标注。
- 拟合结果以「参数表 + 残差图」呈现；参数越界用 `--pm-candidate`/`--pm-refute` 标注并给建议。
- 一键「登记为证据」→ 生成 Evidence（含数据哈希）+ 关联假设选择器。

### 4.4 Physics Lab（CAE）

- 左：参数表单（材料/机械/工艺三组，带单位与推荐范围）；参数集可保存为"实验方案"。
- 中：运行与结果——进度条（阶段名 + 百分比）、过程曲线（实时）、结果指标卡（Δn、R、E、收缩率）。
- 右：参数扫描/优化结果（散点 + 最优标记 + 约束满足着色）。
- 「提交后台任务」走 `dsh-tool-jobs`；可离开面板，状态栏持续显示。
- 结果卡 → 「登记证据」→ 关联假设；「与上次对比」生成差异表。

### 4.5 Evidence（证据账本）

- 表 + 时间线的双视图（可切换）。
- 列：ID、类型（观测/文献/CAE/表征）、极性、强度、引用数、哈希校验状态、时间、登记者。
- 校验失败的哈希用 `--pm-refute` 高亮并禁止引用。
- 行展开：原始 payload、artifact 链接、引用它的假设/边。

### 4.6 Hypothesis（假设看板）

- 列 = 状态：`proposed / conditional / under_test / supported / refuted`。
- 卡片：陈述（截断）、竞争假设数、证据数（支持/反驳）、判别实验是否存在。
- 拖拽迁移状态时**服务端校验**（不合法则弹回并说明原因，如"缺少判别实验"）。
- 卡片详情：判别实验设计（四要素：设计/观测量/若真预期/若假预期）。

### 4.7 Literature

- 检索框（自然语言）+ 结果列表（标题/作者/年份/DOI/是否已入库）。
- 选中 → 右侧阅读器（复用 `dsh-zotero-skill` 或 `@a9i5k4/dsh-literature` 的 UI，通过 slot 或 iframe 嵌入；不可嵌入则新窗口）。
- 「提炼为证据」：Agent 抽取 → 预填 Evidence 表单（DOI、结论、极性）→ 人工确认。

### 4.8 Knowledge（RSI 卡流）

- 三列：`pending`（待审）/ `approved` / `archived`。
- 卡片显示：kind、scope、标题、来源任务、关联实体。
- 审核操作：批准（需选 reviewer）、驳回（必填理由）、升级为机理边（if edge-candidate）。
- 顶部统计：本周新增、批准率、被反驳数。

## 6. 状态与反馈规范

| 状态 | 要求 |
| --- | --- |
| Loading | 骨架屏（形状匹配最终内容），>400ms 才显示，避免闪烁 |
| Empty | 说明"为什么空" + 一个主行动按钮 + 一个次行动 |
| Error | 结构化：`code` + 人话说明 + 可操作建议（重试/查看日志/导出诊断） |
| Streaming | 会话流式渲染；工具卡先占位后填充；不阻塞其他面板 |
| 长任务 | 进度条 + 阶段名 + 可取消 + 后台化；离开面板不中断 |
| 冲突 | 显示"其他人/Agent 已修改" + 差异 + 选择保留 |
| 越权 | 隐藏不可用操作（而非禁用后报错），必要时显示原因 tooltip |

## 7. 动效

- 只用于**状态转换**（面板打开 160ms ease-out、Inspector 内容切换 120ms 淡入、图谱节点高亮 120ms）。
- 禁止：装饰性动画、自动播放、超过 200ms 的过渡。
- 尊重 `prefers-reduced-motion`。

## 8. 可访问性

- 全键盘可达：`Tab` 顺序符合视觉顺序；`⌘K` 命令面板；面板切换 `⌘1..8`。
- 焦点环：2px `--pm-accent`，offset 2px，**不可移除**。
- 图表提供表格替代视图（"查看数据表"）。
- 语义色不单独承载信息（同时用形状/图标/文字）。
- 中文/英文双语：所有文案走 copy 模块，禁止硬编码。

## 9. 设计反模式（禁止）

1. 把科研工作台做成聊天窗口 + 侧边栏。
2. 用彩色卡片墙堆信息（信息密度靠排版与分组，不靠色块）。
3. 图表无单位、无坐标轴标签、无数据来源。
4. 结论不显示证据就呈现。
5. 用 loading spinner 覆盖整页。
6. 面板内嵌套滚动条超过两层。
7. 隐藏当前项目/当前假设等上下文。
8. 自动刷新导致用户正在编辑的表单被重置。

## 10. 验收（视觉与交互）

- 打开应用 3 秒内能回答：我在哪个项目、有几个待验证假设、Agent 在做什么。
- 从任一结论 2 次点击内到达原始证据/数据。
- 图谱条件过滤后，能立即看出"当前工况下哪些机理可能成立"。
- 键盘完成一次完整任务：新建假设 → 关联证据 → 提交审查。
- 深浅色模式下所有语义色与图表序列色均可区分（含色盲模拟）。
