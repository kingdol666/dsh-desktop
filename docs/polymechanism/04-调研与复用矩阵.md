# 04 — 插件生态调研与复用矩阵

> 调研日期：2026-11-19。数据来源：① 本仓库 vendored 运行时清单（`vendor/dsh-runtime/0.2.1-rc.3/manifest.json`，345 个包）② 官方社区插件目录索引 `dsh-plugin-catalog`（**6,245 个插件**，`https://cdn.jsdelivr.net/npm/dsh-plugin-catalog/index.json`）③ 逐个 GitHub API 核实（star/license/最后更新）。**插件是否真存在、许可是否干净、能否在 0.2.1-rc.3 加载，是本项目最大的两个工程风险，必须先解决。**

---

## 0. 一条必须先读的兼容性红线

**`@deepseek-ai/dsh-client-runtime` 不存在于 0.2.1-rc.3 的 vendored 运行时中。** 大量社区插件在 `inject` 里声明它——这类插件在本项目**无法加载**。因此：

- 任何第三方插件在"采纳"前必须做**加载冒烟**（装进测试 profile → 启动 → 检查 Loader 是否报 inject 缺失）。
- **自研插件禁止 `inject: 'clientRuntime'`**，客户端能力只用本项目已验证的 inject 清单（见 `dsh-plugin-desktop/src/client/index.ts` 的 `slots/locale/connection/remote/...`）。
- 只声明 `engines: dsh >= 0.2.1` 且 peer 干净的插件，优先级最高。

## 5. 采纳清单（Phase 0 落地）

### 5.1 必须安装（P0，1 天内完成并冒烟）

```bash
# 1) 文献知识库（用户已选）
dsh plugin --profile poly add dsh-kb-rag
# 2) Zotero 精读（用户已选）
dsh plugin --profile poly add dsh-zotero-skill
# 3) 通用记忆（二选一，先试 mnemon 再试 memory-eternal）
dsh plugin --profile poly add dsh-mnemon
dsh plugin --profile poly add memory-eternal
```

**冒烟断言**（缺一即降级）：
- Host 启动无 `inject` 缺失错误；
- Agent 能看到 `kb_*` / `memory_recall` 工具；
- 一次真实调用成功（`kb_ingest` 一篇 PDF → `kb_search` 命中）；
- 无 `client-runtime` 报错。

### 5.2 备选待验证（P1）

- `dsh-library`（若 kb-rag 的 Python 依赖不可接受，则换它）
- `dsh-litbench`（若需侧栏阅读工作台）
- `dsh-agent-teams`（P4 替换官方 experimental-agent-team）

### 5.3 明确不引入

- `dsh-knowledge`（AGPL-3.0）、`ToPolyAgent`（无 license）、`stca-agent-skill`（NOASSERTION）——许可证风险不可控。

## 6. 风险登记

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 第三方插件 inject `client-runtime` | 安装即失败 | 采纳前冒烟；失败立即换备选；自研插件禁用该 inject |
| `dsh-kb-rag` 需 Python + 模型下载 | 首用阻塞 | 预置 `HF_ENDPOINT=https://hf-mirror.com`；离线则降级 `dsh-library` |
| Zotero 需本地 API + 扩展 | 精读链路阻塞 | 保留 `dsh-literature` 作纯 PDF 方案 |
| 第三方插件随上游升级失效 | 长期维护成本 | 锁定版本、编写 `verify:plugins` 冒烟脚本、只依赖公开工具面（不进内部数据结构） |
| 许可污染 | 无法分发/商用 | 仅采纳 MIT/Apache-2.0；AGPL/无 license 一律不引入 |
